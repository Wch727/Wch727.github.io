这个项目给 TierFlow 的 LoopVL 模型补充了本地部署脚本和网页界面。它沿用官方 Python runtime，主要处理本地运行时会遇到的事情：准备代码和权重、查看模型状态、连续提问，以及不用时释放模型。

目前是**实验性本地部署工具**：已经完成本机测试，尚未验证全新环境安装。模型与推理方法来自上游，这个仓库负责独立的界面与部署包装。

## 按需要加载，而不是打开就占内存

打开网页只检测状态，点击“启动模型”后才加载权重。使用结束可以手动释放，也可以设置空闲自动释放的时间。模型保持加载时，可以连续发送问题，无需每次重新启动。

界面只监听本机地址，图片在本机处理。网页使用 Python 标准库实现，不需要额外安装 Node.js、FastAPI 或 Gradio。

## 图片与文字对话

图片支持上传、拖入和剪贴板粘贴，也提供四张官方示例。对同一张图片可以连续追问；新对话清空历史但保留图片，换图则重新开始上下文。不选图片时也可以进入纯文字对话，移除已有图片会开启文字新对话。

界面接入了六档 H/L 切换、推理提示开关与输出长度设置。它们用于调整运行配置，实际速度和输出表现仍需要结合具体问题观察。

## 部署流程

仓库分别提供官方 runtime 准备、模型校验和网页启动脚本。模型路径可以在配置文件或环境变量中指定，权重与上游代码单独下载，不随这个仓库分发。

```sh
python setup_runtime.py
python verify_model.py
python start_ui.py
```

上面的命令是准备完成后的主要入口。第一次部署仍需按 README 安装依赖并下载完整模型。runtime 固定到已使用过的上游提交，校验脚本检查模型文件，减少版本和文件不完整带来的排查成本。

## 目前验证到哪里

当前网页固定使用 **CPU**，尚未接入 GPU。本机已经完成图片问答和连续对话链路测试，但 CPU 推理耗时较长，历史和输出越长通常越慢。

纯文字模式也只验证了链路可运行：一次简单算术测试在 64 Token 上限内未给出最终数字。因此目前更适合用来观察和尝试这个模型的本地运行方式，通用聊天效果仍有明显限制。

日志、权重、本机配置和缓存均排除在版本管理之外。项目采用 Apache-2.0，下载的模型与官方代码继续遵循各自的上游许可。
